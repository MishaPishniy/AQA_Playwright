# Виправлення архітектури

Дата: 16 листопада 2026 року.

## Контракт тестового середовища

Для оновлених тестів використовуються `BASE_URL`, `TEST_USERNAME`, `TEST_PASSWORD`.
Значення облікових даних не слід додавати до звітів. `getEnv` перевіряє наявність
потрібної змінної під час використання. `username` у custom fixtures можна
перевизначити через `test.use`; авторизована фікстура використовує саме це значення.

Тести входу використовують неавторизовані `page` / `loginPage`. Фікстура
`loginInPage` призначена для тестів, яким уже потрібен каталог після входу.
Локатори й UI-дії розташовані у POM/components, бізнес-перевірки — у тестах.

## Команди

- `npm run typecheck` — перевірка TypeScript без генерації JavaScript.
- `npm run test:list` — список тестів без їх виконання.
- `npm run test:dev` — локальний dev-конфіг із видимим браузером.
- `npm run test:smoke` — локальний smoke-конфіг.
- `npm test` — попередній основний конфіг; спосіб запуску CI не змінено.

Локальні dev/smoke-конфіги використовують спільний base, зберігаючи свої matcher,
нуль retries і попередній нульовий поріг visual-різниці. Основний і CI-конфіги
не змінено за вказівкою користувача. Base знаходить тести за абсолютним шляхом
від власного розташування, незалежно від поточного каталогу shell.

## Валідація та залишкові питання

- TypeScript перевірено; помилку типу аргументу в навчальному `TS/class.ts` виправлено.
- Цільовий Chromium-запуск: 16 функціональних тестів пройшли, 2 visual-тести
  не відповідають наявним еталонам.
- Оригінальні visual-тести з Git HEAD відтворюють ті самі розбіжності:
  102 пікселі для каталогу та 26350 для картки. Рефакторинг не спричинив їх.
- Еталон картки містить Backpack, хоча початковий тест вибирає Z→A і першу
  картку. Потрібно окремо узгодити очікуваний товар перед зміною тесту або еталона.
- Еталони, пороги, skips і retries не змінено для приховування падінь.
- `.gitignore` запобігає додаванню нових env-файлів, але вже відстежувані файли
  залишаються в Git. Їх вилучення з образу потребує окремої міграції CI/CD.
- Dockerfile, .dockerignore, workflow і CI-конфіг залишені без змін.
- Розділення навчальних, API та продуктових наборів із зміною їх запуску в CI
  залишається наступним кроком після погодження CI/CD.
