# SauceDemo — план тестування авторизації

## Обсяг і передумови

- Сайт: https://www.saucedemo.com/.
- Дата перевірки: 12 жовтня 2026 року.
- Кожен сценарій починається в окремому чистому браузерному контексті, без cookies та збереженої сесії. Сценарії незалежні, порядок запуску довільний.
- Якщо не зазначено інше, відкрити головну сторінку й переконатися, що поля `Username`, `Password` та кнопка `Login` видимі.
- Публічні тестові облікові дані сайту: `standard_user` / `secret_sauce`; заблокований користувач: `locked_out_user` / `secret_sauce`.
- Успіх сценарію: виконані всі зазначені очікування. Невідповідність URL, повідомлення чи стану елементів означає провал сценарію.
- Перевіряється поведінка демонстраційного інтерфейсу; цей план не є аудитом серверної безпеки.

## 1. Успішний вхід стандартного користувача

**Початковий стан:** чистий контекст, сторінка входу.

1. Ввести `standard_user` у `Username`.
2. Ввести `secret_sauce` у `Password`.
3. Натиснути `Login`.

**Очікуваний результат:** URL дорівнює `https://www.saucedemo.com/inventory.html`, заголовок сторінки — `Products`, список товарів видимий. Форму входу більше не показано.

**Ознаки провалу:** користувач залишився на сторінці входу, з'явилася помилка або каталог не відображається.

## 2. Неправильний пароль

**Початковий стан:** чистий контекст, сторінка входу.

1. Ввести `standard_user` у `Username`.
2. Ввести `wrong_password` у `Password`.
3. Натиснути `Login`.

**Очікуваний результат:** залишаємося на `https://www.saucedemo.com/`; форма входу видима, каталог недоступний. Повідомлення:

`Epic sadface: Username and password do not match any user in this service`

**Ознаки провалу:** успішний вхід, відсутня помилка або інший текст повідомлення.

## 3. Невідомий користувач

**Початковий стан:** чистий контекст, сторінка входу.

2. Ввести `secret_sauce` у `Password`.
3. Натиснути `Login`.

**Очікуваний результат:** URL залишається `https://www.saucedemo.com/`; каталог недоступний, форма входу видима. Повідомлення:

`Epic sadface: Username and password do not match any user in this service`

**Ознаки провалу:** успішний вхід, відсутня помилка або інший текст повідомлення.

## 4. Обидва поля порожні

**Початковий стан:** чистий контекст, сторінка входу, обидва поля порожні.

1. Натиснути `Login`, не заповнюючи поля.

**Очікуваний результат:** залишаємося на сторінці входу, каталог недоступний. Повідомлення:

`Epic sadface: Username is required`

**Ознаки провалу:** перехід до каталогу, відсутня помилка або повідомлення про пароль замість обов'язкового імені користувача.

**Ознаки провалу:** перехід до каталогу, відсутня помилка або інший текст повідомлення.

## 8. Вихід, закриття доступу до каталогу та повторний вхід

**Початковий стан:** чистий контекст, сторінка входу. Авторизація виконується всередині цього сценарію.

1. Увійти як `standard_user` / `secret_sauce` і перевірити URL каталогу та видимий список товарів.
2. Відкрити меню кнопкою `Open Menu`.
3. Натиснути `Logout`.
4. Перевірити повернення на `https://www.saucedemo.com/`, порожні поля входу, відсутність повідомлення про помилку та прихований каталог.
5. У цьому самому контексті відкрити `https://www.saucedemo.com/inventory.html`.
6. Перевірити повернення на сторінку входу та повідомлення `Epic sadface: You can only access '/inventory.html' when you are logged in.`
7. Знову ввести `standard_user` / `secret_sauce` і натиснути `Login`.

**Очікуваний результат:** після виходу доступ до каталогу закритий; повторна авторизація відкриває `/inventory.html`, `Products` і список товарів.

**Ознаки провалу:** вихід не повернув форму входу, каталог доступний після виходу або повторний вхід не працює.

## 9. Прямий доступ до каталогу без авторизації

**Початковий стан:** новий чистий контекст без попереднього входу.

1. Одразу відкрити `https://www.saucedemo.com/inventory.html`.

**Очікуваний результат:** браузер переходить на `https://www.saucedemo.com/`; форма входу видима, список товарів не відображається. Повідомлення:

`Epic sadface: You can only access '/inventory.html' when you are logged in.`

**Ознаки провалу:** каталог відкрився без авторизації, перенаправлення не відбулося або повідомлення не відповідає очікуванню.

## Автоматизація та результати дослідження

- Поведінку всіх наведених сценаріїв досліджено через локальний Playwright у Chromium з окремими контекстами. Це дослідницькі перевірки, а не збережений набір автотестів.
- `tests/codegen.spec.ts` уже автоматизує основні перевірки сценарію 1: вхід, точний URL каталогу, текст `Products` і видимість `[data-test="inventory-list"]`.
- Наявний автотест повторно запущено командою `npx playwright test tests/codegen.spec.ts --reporter=list`: **3 passed**, Chromium, Firefox, WebKit.
- `tests/seed.spec.ts` містить порожню заготовку; для ізоляції майбутніх тестів слід зберегти стандартний чистий контекст Playwright і не використовувати спільний авторизований `storageState`.
- Для сценаріїв 2–9 потрібно згенерувати окремі автотести. На момент створення плану їх у проєкт не додано.
- Стабільні локатори: `[data-test="username"]`, `[data-test="password"]`, `[data-test="login-button"]`, `[data-test="error"]`, `[data-test="title"]`, `[data-test="inventory-list"]`, `[data-test="logout-sidebar-link"]`.
- Під час дослідження `Logout` мав роль `button`, тому для нього слід використовувати спостережений `data-test` або відповідну роль, а не `getByRole('link')`.
- Інструменти `planner_setup_page` та `planner_save_plan` у сесії недоступні; використано локальний Playwright і збереження Markdown у файловій системі.

## Межі перевірки

Сценарії 2–9 перевірено лише в Chromium; їхній результат у Firefox і WebKit поки не підтверджено. У трьох браузерах виконано наявний позитивний автотест. Очікування плану спираються на досліджену поведінку сайту, оскільки окремої продуктової специфікації не надано.
